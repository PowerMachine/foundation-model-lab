01 / PROBLEM

The research question

Where do batching, queueing, and KV policies stop producing useful SLO goodput under rising load?

02 / CONTRIBUTIONS

What this work adds

01

Paired workload traces

Three scheduler policies consume identical seeded arrivals, separating policy effects from workload variance.

02

Threshold-defined knees

Capacity is reported as a sustainable-to-failing interval under explicit completion, SLO, and terminal-failure gates.

03

Measurement separation

A real tiny CPU fidelity probe is labeled separately from the discrete-event capacity simulation.

03 / SYSTEM

System path

seeded arrivals → scheduler + queue → paged KV model → faults/cancellation → latency + SLO goodput → capacity gate

Paired traces expose scheduler trade-offs and overload knees; a separately labeled tiny CPU probe checks quantization fidelity without claiming integer-kernel speedup.

05 / BOUNDARY

What the evidence does—and does not—support

Claim boundary

Scheduler and capacity results are discrete-event simulation. Fake INT8/INT4 weights run through FP32 kernels; this is not vLLM, GPU, or fleet telemetry.

Next evidence promotion

Replay the same workload against vLLM or SGLang and fit service/KV parameters to real GPU traces.
