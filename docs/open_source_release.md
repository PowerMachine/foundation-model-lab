# Open-source release policy

This checklist defines the public boundary for Foundation Model Lab. It is an engineering release
policy, not legal advice. The conservative default is to publish source code and reproducible
synthetic evidence while keeping weights, private inputs, workstation metadata, and uncertain
derivatives out of Git history.

## 1. License boundaries

The repository's [MIT license](../LICENSE) applies to original source code and documentation only.
It does not automatically relicense models, datasets, generated responses, images, or adapters.

| Asset | Default public decision | Required review before inclusion |
|---|---|---|
| Original Python, scripts, tests, and docs | include | copyright ownership and third-party snippets |
| Original synthetic generators | include | code dependencies and bundled fonts/assets |
| Synthetic samples generated only by this repository | include selectively | no copied template, logo, font, PII, or third-party image; document generation seed and license |
| Model configuration names and local path placeholders | include | remove usernames, hostnames, mount layout, and internal project names |
| Base-model weights or copied tokenizer files | exclude | upstream model license, redistribution terms, and acceptable-use conditions |
| LoRA adapters | exclude by default | base-model license, derivative-work conditions, training-data rights, and export/use restrictions |
| Teacher response caches | exclude by default | source-data rights, model-output terms, memorization risk, and personal/confidential information |
| Public benchmark data | link to the official source | redistribution and derivative-asset terms |
| Internal, clinical, customer, or research-participant data | exclude | formal data-owner, IRB/consent, privacy, and institutional approval |

For every released model-derived asset, create a short model card recording the base model and
revision, upstream license, training-data origin, intended use, limitations, evaluation protocol,
and the exact decision that permits redistribution. If any field is uncertain, publish the recipe
and metrics without the weight or cache.

## 2. Repository boundary

The two local checkpoints used by the flagship are referenced, never vendored: the upstream
[Qwen3-VL-8B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct) and
[Qwen3-VL-32B-Instruct-FP8](https://huggingface.co/Qwen/Qwen3-VL-32B-Instruct-FP8)
model cards declare Apache-2.0. That metadata does not make every adapter, training input, or
teacher output automatically releasable; those derived artifacts still follow the table above.

Expected public source:

- `src/`, `scripts/`, `tests/`, reviewed `configs/`, and `.github/workflows/`;
- documentation, container recipes, and the top-level license;
- small synthetic examples and sanitized evidence bundles when they are reproducible.

Expected private/external state:

- local model stores, Hugging Face and Torch caches, virtual environments, and temporary files;
- checkpoints, merged weights, adapters pending license review, optimizer state, and tensor dumps;
- raw or accepted teacher caches, full prediction dumps over non-public data, and private indexes;
- `.env` files, tokens, SSH material, cloud credentials, service-account files, and shell history;
- hostnames, usernames, absolute mount paths, scheduler IDs, internal URLs, and infrastructure logs.

The existing [ignore rules](../.gitignore) are a guardrail, not a release decision. Before the
first commit, explicitly remove patch backups (`*.orig`, `*.rej`), caches, and generated bytecode;
verify that none were already added to the index or history.

## 3. Secrets and private-data checks

Run these checks from a clean release worktree. Treat matches as items to inspect, not automatic
proof that a secret exists.

```bash
git status --short --untracked-files=all
git ls-files

rg -n --hidden --glob '!.git/**' \
  '(hf_[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}|BEGIN (RSA |OPENSSH |EC )?PRIVATE KEY|api[_-]?key|client[_-]?secret|password[[:space:]]*[=:])' .

rg -n --hidden --glob '!.git/**' \
  '(/home/|/data/|hostname|internal\.|corp\.|s3://|gs://)' .

find . -type f -size +20M -print
find . -type f \( -name '*.orig' -o -name '*.rej' -o -name '*.pyc' \) -print
```

If Git history already exists, scan history as well as the working tree. A tool such as `gitleaks`
is recommended, but it does not replace manual review:

```bash
gitleaks detect --source . --no-banner
git rev-list --objects --all
```

If a credential ever entered Git history, deleting the visible file is insufficient. Revoke or
rotate the credential first, then rewrite history using an approved process and verify every
remote and fork that may still contain it.

### Data-specific review

For every image, JSONL row, prediction, and report proposed for release:

- confirm the source and redistribution right;
- inspect rendered pixels as well as filenames and JSON fields;
- remove names, IDs, addresses, faces, signatures, QR/barcodes, document numbers, and free-text PII;
- strip EXIF and other embedded metadata from images;
- check prompts, references, and teacher answers for private text or memorized passages;
- make sure train/evaluation membership does not reveal confidential dataset composition;
- record whether the item is original synthetic, public third-party, or private and excluded.

Synthetic data is not automatically safe. A synthetic template can still contain a real logo,
copied document layout, bundled proprietary font, or seed text derived from private data.

## 4. Reproducible public artifact policy

Public artifacts must make a claim reviewable without exposing the private execution environment.
Use the fail-closed [sanitized exporter](public_evidence.md), then link the resulting bundle from
the [public evidence index](../public-evidence/README.md). Do not assemble a release bundle by
copying a raw runtime directory. The current source-controlled shape is:

```text
public-evidence/<track>/<run-id>/
├── evidence_manifest.json      # source/public SHA-256, redactions, allowlist, claim boundary
├── result.json
├── provenance.json             # optional, sanitized when present
├── report.html
├── *.svg
└── explicitly allowlisted safe text files
```

Apply these rules:

1. **JSON is canonical.** HTML, SVG, and PNG files are derived views and must be regenerable.
2. **Claims require evidence.** A README result links to a tracked evidence bundle or is labeled
   pending. Code presence alone is not a result.
3. **Preserve claim level and source kind.** Keep `simulated`, scripted-control, actual-CPU,
   fake-quantization, backend, status, seed, sample count, and optimizer steps visible. Never rename
   a mock run to look like a model run, a simulator value to look measured, a scripted policy to
   look like an LLM, or fake quantization to look like packed-integer execution.
4. **Publish exact inputs when possible.** Include only releasable synthetic evaluation rows and
   their generator seed. For non-redistributable benchmarks, include IDs/hashes and retrieval
   instructions, not copied examples.
5. **Sanitize provenance.** Retain package versions, accelerator type, model identifier/revision,
   decoding parameters, config hash, input hashes, wall time, and peak VRAM. Replace absolute
   paths, username, hostname, IP, scheduler/job ID, and internal mount names with neutral fields.
6. **Keep an integrity link.** Store the SHA-256 of the private raw result in the public provenance
   when policy permits; record that the public file is a redacted derivative.
7. **Bound size.** Prefer adapter metadata, metrics, representative synthetic predictions, and
   vector plots. Do not use Git for base weights, optimizer state, caches, or bulk images. Use a
   separately licensed release mechanism only after review.
8. **Keep failures.** An infrastructure or negative-result artifact may be published when
   sanitized. Do not silently omit failed seeds from an aggregate.
9. **Regenerate in CI.** At least one CPU/mock evidence path must run without network or local
   model files. Real-model artifacts remain reproducible from documented local prerequisites.
10. **Version the protocol.** Record commit SHA, config version, dataset/generator version, and
    evaluation code version for every promoted result.
11. **Bound the portfolio claim.** Do not describe controlled toy studies as production validation,
    frontier-scale infrastructure, equivalence to an S-tier employer/research lab, or proof of
    readiness for a particular role level.

Do not commit the unredacted runtime artifact directory and then attempt to clean it in a later
commit. Produce the public derivative outside Git history, inspect it, and add only that bundle.

### Sanitized export commands

Load the ignored `.env` through `scripts/env.sh`, then regenerate each checked-in derivative from
its external source. The visual reward run needs an explicit boundary because its older
`result.json` predates the repository-wide field; JSONL audit/preference rows remain private.

```bash
source .venv/bin/activate
source scripts/env.sh

python scripts/export_public_evidence.py \
  "$FMLAB_DATA_ROOT/artifacts/vlm/visual-reward-environment" \
  public-evidence/vlm/visual-reward-environment \
  --include environment_spec.json \
  --claim-evidenced "Measured environment-and-grader behavior on deterministic synthetic visual tasks." \
  --not-evidenced "VLM generation quality or online RL" \
  --not-evidenced "human-preference agreement or production safety" \
  --not-evidenced "distributed rollout scale"

python scripts/export_public_evidence.py \
  "$FMLAB_DATA_ROOT/artifacts/agent/reliable-agent-benchmark" \
  public-evidence/agent/reliable-agent-benchmark \
  --include run_manifest.json \
  --include task_manifest.json \
  --claim-evidenced "Local execution of 12 immutable microtasks under two scripted harness controls, with outcome/process grading, bounded retry, and exact resume." \
  --not-evidenced "LLM or coding-agent model capability" \
  --not-evidenced "OS sandbox or network-isolation security" \
  --not-evidenced "SWE-bench scale or production long-horizon reliability"

python scripts/export_public_evidence.py \
  "$FMLAB_DATA_ROOT/artifacts/systems/inference-dynamics" \
  public-evidence/systems/inference-dynamics \
  --include actual_probe.json \
  --include capacity_sweep.json

python scripts/export_public_evidence.py \
  "$FMLAB_DATA_ROOT/artifacts/distributed/ddp-correctness" \
  public-evidence/distributed/ddp-correctness
```

Inspect the staged outputs, run the focused policy tests, scan the public tree again, and verify
the hashes recorded for every published file. This example checks one bundle; repeat it for all
four directories linked by the index.

```bash
pytest -q tests/test_public_evidence.py
rg -n '(/home/|/data/|BEGIN .*PRIVATE KEY|hf_[A-Za-z0-9]{20,})' public-evidence

bundle=public-evidence/systems/inference-dynamics
jq -r '.files[] | "\(.public_sha256)  \(.path)"' \
  "$bundle/evidence_manifest.json" | \
  (cd "$bundle" && sha256sum -c -)
```

The `rg` command is expected to print no matches. A successful checksum pass validates public bytes
against the manifest; it does not validate the private-source hash, licensing, or semantic privacy.

## 5. Reproducibility acceptance criteria

A release candidate is reproducible when a reviewer can determine:

- which hypothesis and claim level the run addresses;
- the base model identifier and whether files were local-only;
- the exact data split rule, seed, manifest fingerprint, and sample budget;
- which tokens contributed to loss and which parameters were trainable;
- optimizer steps, dtype, pixel/token budget, generation settings, and stop reason;
- before/after or baseline comparisons on identical held-out examples;
- task-slice metrics, uncertainty method, wall time, peak memory, and failure cases;
- whether every number came from a mock backend, a real smoke run, or a controlled experiment.

The shared criteria are defined in the [research protocol](research_protocol.md). VLM releases
must additionally follow the [response-distillation protocol](vlm_response_distillation.md) when
teacher-generated targets are involved.

## 6. Release checklist

### Scope and rights

- [ ] Name the release owner and freeze the commit under review.
- [ ] Inventory every code, data, model-derived, and visual asset.
- [ ] Confirm original-code ownership and all dependency notices.
- [ ] Verify upstream terms for every referenced model and dataset revision.
- [ ] Exclude weights, adapters, caches, or outputs whose redistribution right is unclear.
- [ ] Add dataset/model cards for any asset intentionally released.

### Repository hygiene

- [ ] Remove `__pycache__`, `.pytest_cache`, `.ruff_cache`, `*.orig`, and `*.rej` files.
- [ ] Replace workstation paths, usernames, hostnames, and internal labels in public configs/docs.
- [ ] Verify `.env`, model files, checkpoints, generated caches, and large tensors are ignored and
      untracked.
- [ ] Inspect both untracked files and the full Git history with secret-scanning tools.
- [ ] Review image pixels, metadata, JSONL free text, HTML, SVG, and logs for private information.
- [ ] Confirm there are no symlinks pointing outside the repository.

### Technical verification

- [ ] Create a fresh CPU environment and install from `pyproject.toml`.
- [ ] Run `ruff check src scripts tests`.
- [ ] Run `ruff format --check src scripts tests`.
- [ ] Run `pytest -q` with `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1`.
- [ ] Run the deterministic toy suite and both VLM mock/wiring paths from documented commands.
- [ ] Run the visual-reward and reliable-agent scripted controls, inference simulator/CPU probe,
      and actual two-rank CPU/Gloo DDP path from the documented standalone commands.
- [ ] Regenerate sanitized bundles with `scripts/export_public_evidence.py`, verify every manifest
      public hash, and confirm the public index links the promoted result.
- [ ] Validate every checked-in JSON and open every published HTML/SVG/PNG artifact.
- [ ] Confirm a missing local model or insufficient VRAM fails clearly without partial corruption.

### Evidence review

- [ ] Reconcile every README number with a tracked `result.json`.
- [ ] Confirm train/evaluation source groups do not overlap.
- [ ] Verify simulated results are visibly labeled in JSON, plots, captions, and prose.
- [ ] Keep scripted-policy, deterministic-simulator, actual-CPU, and fake-quantization evidence
      classes separate in the README, report, result, and manifest.
- [ ] Publish all seeds selected by the protocol, including failures and negative results.
- [ ] Recompute aggregate metrics from the released per-example evidence.
- [ ] Check that confidence intervals and task slices use the frozen evaluation manifest.
- [ ] Record storage, wall time, peak VRAM, and any interrupted external workload.

### Final publication

- [ ] Review `git diff --cached` file by file.
- [ ] Verify the top-level license, citation instructions, and limitations are visible.
- [ ] Confirm no claim implies production validation, frontier-scale equivalence, employer
      endorsement, or readiness for a particular seniority level.
- [ ] Tag an immutable version and attach checksums for separately hosted artifacts.
- [ ] Re-clone the public repository in a clean directory and repeat the CPU/offline quickstart.
- [ ] Open the rendered GitHub README and verify every relative link.
- [ ] After publication, perform one final remote secret scan and archive the signed release notes.

Only after all applicable boxes are complete should a smoke result be promoted to an experiment
claim or an adapter/cache be attached to a public release.
